# deviceFile 单元测试用例说明

- 被测文件：`system/include/deviceFile.h`（构造已内联，无同名 `.cpp`）
- 测试代码：`test/system_tests/deviceFile_test/`，按职责分三个文件
  - `deviceFile_test.cpp` —— 测试驱动：编译期契约（IF-00）、按维度编排用例、汇总与清理；不含用例、不持被测对象
  - `deviceFile_cases.cpp` / `deviceFile_cases.h` —— 测试用例：IF/DS/EP 共 22 个（IF-00 为编译期契约，落在驱动中），被测对象在用例内就地构造
  - `deviceFile_stub.h` —— 桩模块：`DeviceFileProbe`、`LockProbe`、伪节点树夹具与断言辅助（纯头文件，无 `.cpp`）
- 测试范围：**仅 `deviceFile` 基类本身**；CPUFile / NPUFile 包装层、CPU / NPU 设备层不在本文范围内
- 测试替身：`DeviceFileProbe`（派生类把 `readFreqTable` 与受保护成员提升为 public；`LockProbe` 记录锁回调次数与锁内表长）
- 伪节点树：`build/test_fake_devicefile/<用例号>/`，套件启动与结束时自动清理

## 运行方式

仓库根目录执行（相对路径，避免含中文的绝对路径被 MinGW 误编码）：

```powershell
g++ -std=c++17 -Wall -Wextra -O2 -g -I. -Itest `
    test/system_tests/deviceFile_test/deviceFile_test.cpp `
    test/system_tests/deviceFile_test/deviceFile_cases.cpp `
    common/src/FileService.cpp -o build/deviceFile_test
.\build\deviceFile_test.exe
```

Linux / 容器内把续行符换成 `\`，运行 `./build/deviceFile_test`。

`make test` 无需额外配置：顶层 Makefile 以 `*_test.cpp` 为驱动，自动把**同目录其余 `.cpp`**（即 `deviceFile_cases.cpp`）一并编入，桩模块是头文件，随驱动展开。

## 判定准则

- 进程退出码 `0`；
- 末行输出 `[deviceFile] passed N, failed 0`；
- 任一 `CHECK` 失败会打印 `文件:行:表达式`，并让退出码非 0。

本次运行结果：`[deviceFile] passed 75, failed 0`。

## 一、接口（IF）

### IF-00 编译期契约：抽象基类 + 虚析构

- **输入数据**：无（编译期类型信息）。
- **前置条件**：包含 `system/include/deviceFile.h`。
- **测试步骤**：编译本套件，令两条 `static_assert` 生效。
- **预期输出**：`std::is_abstract_v<deviceFile>` 与 `std::has_virtual_destructor_v<deviceFile>` 均为真，编译通过。

### IF-01 构造：四个注入值原样保存，频率表为空

- **输入数据**：`freqPath = build/test_fake_devicefile/if01`，`statPath = <同目录>/stat`，`freqMin = 1200000`，`freqMax = 2400000`；目录内不放任何节点。
- **前置条件**：`if01` 为空目录；`DeviceFileProbe` 可构造。
- **测试步骤**：构造对象；依次读取 `freqPath()`、`statPath()`、`freqMin()`、`freqMax()`、`table()`。
- **预期输出**：四个 getter 与注入值完全相等；`table()` 为空。

### IF-02 构造不读节点（懒加载）

- **输入数据**：`if02/available_frequencies` 内容 `"1000000 2000000\n"`；构造参数 `freqPath = statPath = if02`。
- **前置条件**：节点文件已写入且可读。
- **测试步骤**：构造对象后先查 `table()`；再以 `readFreqTable(1, "available_frequencies", lock)` 显式装载一次。
- **预期输出**：构造后 `table()` 仍为空（证明构造期未读文件）；显式调用返回 `true`，`table() == {1000000, 2000000}`。

### IF-03 基类只读 `freqPath`，不碰 `statPath`

- **输入数据**：`if03/freq/available_frequencies = "1000000 2000000\n"`；`if03/stat/available_frequencies = "9000000\n"`（诱饵）。
- **前置条件**：两目录与同名节点均存在。
- **测试步骤**：以 `freqPath = if03/freq`、`statPath = if03/stat` 构造；调用 `readFreqTable(1, "available_frequencies", lock)`。
- **预期输出**：返回 `true`，`table() == {1000000, 2000000}`（取自 freqPath）；`lock` 调用 1 次。

### IF-04 路径原样保存：尾斜杠可读、空路径读失败

- **输入数据**：`if04/available_frequencies = "1000000\n"`；对象 A：`freqPath = if04/`、`statPath = ""`；对象 B：`freqPath = ""`、`statPath = ""`。
- **前置条件**：`if04` 节点已写入。
- **测试步骤**：A 读取 getter 后调用 `readFreqTable(1, "available_frequencies", lock)`；B 以空路径调用同一方法。
- **预期输出**：A 的 `freqPath()` 保留结尾 `/`、`statPath()` 为空串；`if06//available_frequencies` 可读，返回 `true`，`table() == {1000000}`。B 返回 `false`、`lock` 调用 0 次、`table()` 为空。

## 二、局部数据结构（DS）

### DS-01 表不变量：乱序 + 重复 → 升序去重

- **输入数据**：`ds01/available_frequencies = "3000 1000 2000 1000\n"`。
- **前置条件**：`DeviceFileProbe` 以 `ds01` 构造，`freqMin = freqMax = 0`。
- **测试步骤**：`readFreqTable(1, "available_frequencies", lock)`；读取 `table()`；调用不变量检查 `sortedUniquePositive`。
- **预期输出**：返回 `true`；`table() == {1000, 2000, 3000}`；升序、无重复、全为正三项均成立。

### DS-02 非正值剔除

- **输入数据**：`ds02/available_frequencies = "0 -1000 2000\n"`。
- **前置条件**：同上，收窄值均为 0。
- **测试步骤**：装载一次并读取 `table()`。
- **预期输出**：返回 `true`；`table() == {2000}`（0 与负值不进入档位表）。

### DS-03 重复装载覆盖旧表

- **输入数据**：首次 `ds03/available_frequencies = "1000 2000 3000\n"`；随后改写为 `"5000\n"`。
- **前置条件**：首轮装载成功。
- **测试步骤**：首轮装载并断言；覆盖文件后再次装载并断言。
- **预期输出**：首轮 `table() == {1000, 2000, 3000}`；第二轮 `table() == {5000}`（覆盖，不是追加）。

### DS-04 装载失败保留旧表

- **输入数据**：`ds04/available_frequencies = "1000 2000\n"`；首轮成功后删除该节点。
- **前置条件**：首轮装载成功、表为 `{1000, 2000}`。
- **测试步骤**：删除节点；再次调用 `readFreqTable`；读取表与锁次数。
- **预期输出**：第二次返回 `false`；`table()` 仍为 `{1000, 2000}`；本次 `lock` 调用 0 次。

### DS-05 收窄边界：等于上下限的档位保留

- **输入数据**：`ds05/available_frequencies = "1000 2000 3000\n"`；`freqMin = 2000`，`freqMax = 3000`。
- **前置条件**：`DeviceFileProbe` 以该收窄值构造。
- **测试步骤**：装载一次并读取 `table()`。
- **预期输出**：返回 `true`；`table() == {2000, 3000}`（`f == min`、`f == max` 均保留）。

### DS-06 单侧收窄：另一侧 0 表示不限

- **输入数据**：同一节点 `"1000 2000 3000\n"`；对象 A：`min = 2000, max = 0`；对象 B：`min = 0, max = 2000`。
- **前置条件**：A、B 分别构造。
- **测试步骤**：各自装载一次并读取 `table()`。
- **预期输出**：A `table() == {2000, 3000}`；B `table() == {1000, 2000}`。

### DS-07 负收窄值按「不限」处理（越界入参的特征化）

- **输入数据**：`ds07/available_frequencies = "1000 2000 3000\n"`；`freqMin = -5`，`freqMax = -1`。
- **前置条件**：设计前置条件为收窄值非负，本用例故意越界。
- **测试步骤**：装载一次并读取 `table()`。
- **预期输出**：返回 `true`；`table() == {1000, 2000, 3000}`（`> 0` 才参与比较，负值等价于不限）。

## 三、执行路径（EP）

### EP-01 全量装载：true + 锁 1 次 + 写表在锁内

- **输入数据**：`ep01/available_frequencies = "1000000 2000000\n"`；`freqMin = freqMax = 0`。
- **前置条件**：表初始为空。
- **测试步骤**：以 `readFreqTable(1, "available_frequencies", lock)` 装载；读取锁次数与 `lock.tableSizeInsideLock()`。
- **预期输出**：返回 `true`；`lock.calls() == 1`；`tableSizeInsideLock() == 2`（回调返回前表已写入，证明写在 `withLock` 内）；`table() == {1000000, 2000000}`。

### EP-02 部分收窄：true + 子集

- **输入数据**：`ep02/available_frequencies = "1000000 2000000 3000000\n"`；`freqMin = 1500000`，`freqMax = 2500000`。
- **前置条件**：同上。
- **测试步骤**：装载一次并读取 `table()`。
- **预期输出**：返回 `true`；`table() == {2000000}`。

### EP-03 全部低于下限：false + 保留整表

- **输入数据**：`ep03/available_frequencies = "1000000 2000000 3000000\n"`；`freqMin = 5000000`，`freqMax = 6000000`。
- **前置条件**：收窄后候选为空。
- **测试步骤**：装载一次；读取返回值、表与锁次数。
- **预期输出**：返回 `false`；`table() == {1000000, 2000000, 3000000}`（退化为未收窄整表）；`lock.calls() == 1`。

### EP-04 全部高于上限：false + 保留整表

- **输入数据**：同一节点；`freqMin = 0`，`freqMax = 500000`。
- **前置条件**：收窄后候选为空。
- **测试步骤**：装载一次；读取返回值、表与锁次数。
- **预期输出**：返回 `false`；`table() == {1000000, 2000000, 3000000}`；`lock.calls() == 1`。

### EP-05 矛盾配置 `min > max`：false + 保留整表

- **输入数据**：同一节点；`freqMin = 3000000`，`freqMax = 1000000`。
- **前置条件**：两侧条件同时生效会把整表剔空。
- **测试步骤**：装载一次；读取返回值、表与锁次数。
- **预期输出**：返回 `false`；`table() == {1000000, 2000000, 3000000}`；`lock.calls() == 1`。

### EP-06 节点缺失：false + 不取锁

- **输入数据**：`ep06` 为空目录；`readFreqTable(1, "available_frequencies", lock)`。
- **前置条件**：节点文件不存在。
- **测试步骤**：调用一次；读取返回值、锁次数与表。
- **预期输出**：返回 `false`；`lock.calls() == 0`；`table()` 为空。

### EP-07 空文件：false + 不取锁

- **输入数据**：`ep07/available_frequencies` 为空文件。
- **前置条件**：`FileService::read` 对空文件返回空串。
- **测试步骤**：调用一次；读取返回值、锁次数与表。
- **预期输出**：返回 `false`；`lock.calls() == 0`；`table()` 为空。

### EP-08 全垃圾内容：false + 不取锁

- **输入数据**：`ep08/available_frequencies = "abc def\n"`。
- **前置条件**：内容不含任何数字。
- **测试步骤**：调用一次；读取返回值、锁次数与表。
- **预期输出**：返回 `false`；`lock.calls() == 0`；`table()` 为空。

### EP-09 半截垃圾：只取到错误前的档位

- **输入数据**：`ep09/available_frequencies = "1800000 abc 2000000\n"`。
- **前置条件**：`parseFreqTable` 用 `istringstream >> long long` 顺序取值。
- **测试步骤**：装载一次并读取表与锁次数。
- **预期输出**：返回 `true`；`table() == {1800000}`（遇 `abc` 即停止，后续 `2000000` 被截断，属现状行为）；`lock.calls() == 1`。

### EP-10 非法 divisor：false + 不取锁

- **输入数据**：`ep10/available_frequencies = "1000000\n"`；先以 `divisor = 0`、再以 `divisor = -1000` 调用。
- **前置条件**：节点内容合法，仅倍数非法。
- **测试步骤**：两次调用分别读取返回值、锁次数与表。
- **预期输出**：两次均返回 `false`；`lock.calls() == 0`；`table()` 为空。

### EP-11 CRLF 与逗号分隔

- **输入数据**：`ep11/available_frequencies = "1000000,\r\n2000000\r\n3000000\n"`。
- **前置条件**：内核节点常见形态（逗号、CRLF）。
- **测试步骤**：装载一次并读取表。
- **预期输出**：返回 `true`；`table() == {1000000, 2000000, 3000000}`。

## 不在本套件范围

- `CPUFile` / `NPUFile` 包装层的节点名与单位折算（`scaling_available_frequencies` / `available_frequencies`、divisor 1 / 1000）：属各自设备文件层的测试；
- `CPU` / `NPU` 层的错误码映射（`freqUnavailable` 3002、`refreshInfoFalse`）与调频副作用：属于设备层集成测试；
- `parseFreqTable` 的数字文法、`FileService` 的分块读取：属各自单元测试；
- 并发安全：`LockProbe` 只验证「写发生在锁回调内」，真正的数据竞争建议用 `-fsanitize=thread` 跑一次读写混合场景。
